## 2. Method (exact replication + extension of `mahonian.py`)

The runner reuses `mahonian.py`'s defining recurrence verbatim: the coefficient
list of `prod_{d=1}^{m}(1 + q + ... + q^{d-1})` is built by the running-sum
convolution (`run += poly[k]; run -= poly[k-d]`) — exact machine-checked
integers throughout. Two changes for scale, neither touching exactness:

1. **Incremental product.** Instead of rebuilding the polynomial from scratch
   per `m` (as `mahonian.py --mmax` does, `O(m^4)` total), the product is grown
   one factor per `m` and certified after each factor (`O(m^3)` total). The
   coefficients at each stage are identical by construction (same recurrence,
   same factors), and are re-validated per `m` by check C1 below (length
   `N+1 = m(m-1)/2 + 1`, palindromy, strict positivity).
2. **Integer-only minimum scan.** The full scan over all interior `k` keeps the
   running best ratio as a numerator/denominator pair and compares by integer
   cross-multiplication (`num * best_den < best_num * den`) — exactly
   `mahonian.py`'s `min_ratio`, no `Fraction` construction in the hot loop.

`sigma^2 = m(m-1)(2m+5)/72` is held as an exact `Fraction`; `varfit =
sigma^2 (r_m - 1)` is an exact `Fraction`; all six checks (C1–C6, §3) are
exact comparisons of integers/`Fraction`s. Floats occur only in the printed
table columns (`r-1`, `varfit`, `mfit`), never in a verdict.

**Cross-validation against the citable ledger:** the smoke run reproduces NC-1
/ F2_PROOF_DRAFT.md §0 exactly — `varfit(4) = 0.8426`, `varfit(5) = 7/8`,
`varfit(6) = 187/216 = 0.8657407...` (the sharp constant, equality case),
`varfit(40) = 0.97338` (ledger: `0.9734`), and (§3 below) `varfit(150) =
0.99282`, the merge editor's `extend150.py` endpoint value, to all quoted
digits. The `m = 4` exception (argmin `= 2 != floor(N/2) = 3`, `|argmin - N/2|
= 1`) is reproduced as the ledger's "statement correction 2" demands.

## 4. min/argmin behavior vs the F2 predictions

F2 predicts (F2_PROOF_DRAFT.md, Prop 2.2/Cor 2.3 + Theorem A): `varfit ->
1` from below with `varfit = 1 - (27/25)/m + O(m^{-2})`, i.e. `mfit :=
m(1 - varfit) -> 27/25 = 1.08`, argmin exactly central, min = central ratio.
Measured (from `analyze_m200.py` over the exact table; display precision):

| m | varfit | mfit = m(1-varfit) | m(1.08 - mfit) |
|---|---|---|---|
| 40 | 0.9733807895 | 1.06477 | 0.6092 |
| 100 | 0.9892455557 | 1.07544 | 0.4560 |
| 150 | 0.9928186537 | 1.07720 | 0.4200 |
| 200 | 0.9946100211 | 1.07800 | 0.4000 |
| 300 | 0.9964042467 | 1.07873 | 0.3810 |
| 400 | 0.9973023300 | 1.07907 | 0.3720 |

Behavior vs prediction, all consistent:

1. **argmin/min structure:** exactly central at every `m in [5, 400]`; min =
   central ratio exactly; odd-`N` flat step exactly as G5 states. Zero
   exceptions in 396 rows beyond `m = 4`.
2. **First order:** `mfit` increases monotonically toward `1.08` (never
   decreases at display precision for `m >= 7`), reaching `1.07907` at
   `m = 400` — deficit `9.3e-4`, i.e. `O(1/m)` convergence to `27/25` as
   predicted by Lemma 1.2/NC-3 (`27/25` with `O(1/m)` drift).
3. **Second order:** `m(1.08 - mfit)` drifts slowly downward `0.42 -> 0.37`
   over `m = 150..400` — consistent with a genuine `O(m^{-2})` coefficient of
   order `~0.4` in `varfit` plus a smaller third-order term, and comfortably
   inside any `C'/m^2` with `C' <= 20` (the G4/NC-13 slack condition). No sign
   of anomalous drift that would threaten the refined law's shape.
4. **Sharp constant:** the part-(c) bound `varfit >= 187/216 = 0.86574...`
   holds with equality only at `m = 6` and margin growing to `0.1316` at
   `m = 400`; the finite check side of G4 is now done for any threshold
   `m_1 <= 400`.
